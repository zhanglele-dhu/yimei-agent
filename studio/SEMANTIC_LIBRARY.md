# 案例分类与创作意图

## 资料与索引

原始案例 ZIP、原图、正文和 OCR 只读保留。`semantic.py` 将案例标注保存到 `outputs/studio/catalog/{bundle_id}.json`，通过 bundle_id + case_id、原帖 URL 和源文本 SHA-256 对应到原始资料。

三个分类维度是项目、内容类型和具体话题。内容类型区分科普、对比选型、滤片解析、术后护理、咨询流程、体验分享、避坑验真、价格预算和其他。先产生规则分类，用户点击“补全 AI 分类”后，每次最多十篇交给 DeepSeek 阅读标题、正文和 OCR；每批落盘，可中断后继续。模型错误不会被标成已完成。

2026-10-24 当前资料包的 87 篇已全部真实调用模型分类，未移动或修改爬虫源文件。可阅读分类 Markdown 或 CSV；网页“案例资料”支持项目、类型与标题/话题筛选，原帖链接和采集快照点赞数可查看。

## 从一句需求开始

首页“创作需求”→“理解需求并开始”：服务端先用 CreationIntent 识别项目、类型、目标、受众、必须覆盖内容、避免跑偏的方向、形式和页数，再按项目和内容类型筛选参考，最后由模型评相关性并结合采集快照点赞排序。科普可借鉴对比、滤片信息卡，但不会因咨询帖点赞高就套用咨询流程。无匹配案例会停在无匹配状态。

语义识别失败时明确标为规则识别，绝不把规则输出称作模型理解。仅在项目或目标无法确定时请求澄清；缺少具体型号资料留待后续核对，不拦住已经明确的创作任务。`GET /api/catalog` 返回分类与来源；`POST /api/catalog/classify` 逐批补全分类；`POST /api/intent` 可预览理解，不创建任务。

每个新任务存储 intent 和 intent_understanding。拆解、退回重做和草稿调用都携带同一个 creation_intent 与 INTENT 来源。科普允许全文字信息卡，不默认插入实拍、门店聊天、到店面诊或营销结尾。空白事实保持空白，不注入示例设备、价格或门店身份。已有草稿保持原确认状态，需用新的科普需求重新创作。

## 验证边界

真实模型测试在临时任务库中执行：输入“M22仪器科普，讲清设备区别与滤片知识，不要到店咨询清单，不要实拍”，选中《光子嫩肤各仪器区别，一图懂》，大纲为三张文字信息卡，草稿标题覆盖设备区别与滤片知识。结果位于 `outputs/studio/semantic-review-20261024/live-science-flow.json`。测试采用原帖 OCR 与正文，关闭了视觉分析和额外知识库检索；不代表对医学事实做了独立验证，也未自动修改用户旧草稿。

离线接口测试验证分类筛选、未知项目、规则降级、源资料不变和意图传递。浏览器测试使用模拟模型、真实 API 和 Chromium，验证六篇护理案例筛选、一句话开始、没有示例事实、未自动代替用户通过审核，以及窄屏无横向溢出。
